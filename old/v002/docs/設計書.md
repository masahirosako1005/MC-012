# 旅の続き便 設計書（v002）

N西市の観光客向けWebアプリ。認証は置かない。訪問先のサジェスチョンを1本のリストで出し、季節・食・人の3枚を初期表示する。本人がスポットと理由を入れ替え、編集後の1枚だけをこの端末に保存する。

スポット名は星凪諸島スタンプラリーのサンプルを、N西市の実証用コンテンツとして使っている。再訪そのものはサンプルでは未観測であり、このアプリは予測をしない。

## 1. システム構成

ブラウザだけで動く。サーバ処理、外部API、外部DB、クラウドストレージは使わない。

```text
ブラウザ
  index.html
    css/v002.css
    img/hero.svg     海辺の町・桜・旅人のオリジナルキービジュアル
    js/catalog.js   スポットと季節の静的データ
    js/engine.js    候補の採否
    js/store.js     localStorage の読み書きと検証
    js/ui-v002.js   画面描画
```

| 区分 | 内容 |
| --- | --- |
| 実行場所 | このPCのブラウザ。スマートフォンとタブレットは開発者ツールの画面幅で確認する |
| 配信 | 静的ファイル。`v002` をローカルに開く |
| 保存 | `localStorage` キー `nishi-tsuduki-v002`。ログイン情報は持たない |
| 外部通信 | なし。Content-Security-Policy で `self` 以外を拒否する |
| ライブラリ | なし。ライセンス対象の第三者コードは含まない |
| 背景 | オリジナルSVG。海辺の町、桜の坂道、青空、特定作品を参照しない旅人 |

画面遷移は URL のハッシュで行う。

| ハッシュ | 画面 |
| --- | --- |
| `#/home` | はじめに |
| `#/suggest` | 候補 |
| `#/cards` | 3枚の編集 |
| `#/promise` | 残した1枚 |
| `#/log` | この端末に残した季節 |

## 2. 画面設計

参考アプリの「白い固定ヘッダー、大きなキービジュアル、白地のカード、5項目の固定ボトムナビ、中央の主要操作」を構成の参考にした。画像、ロゴ、配色、アイコンを複製していない。

画面はスマートフォン幅520pxを上限に中央配置する。ホーム上部にオリジナルの海辺・桜・旅人のキービジュアルを大きく表示する。白い固定ヘッダー、半透明・ぼかし・角丸・控えめな影のカード、白基調のボタン、青緑のアクセントを使う。ボトムナビ中央の「編集」を円形で強調する。一般的な管理画面や派手なゲーム画面にはしない。

文字はカタログと固定文だけを `textContent` で出す。利用者の自由入力欄はない。

### S01 はじめに

- 白いヘッダー、全面キービジュアル、タイトル「旅の続き便」、キャッチコピーを表示する。
- 現地モードと帰宅後モードを切り替える。
- この端末で見ている季節を、春夏秋冬から選ぶ。季節は通知条件の確認用であり、外部の時計APIは使わない。
- 「段差、バス、休憩を先に表示する」を選ぶと、移動負担を景色の文より上に出す。
- 保存した1枚の季節と、見ている季節が一致し、未確認のときだけ「約束の季節になりました」をアプリ内に出す。プッシュ通知は送らない。
- 「いまから行ける場所 / 次の旅の候補」と「3枚を編集する」の2つの大きな導線を出す。
- 候補の先頭2件をカードで抜粋する。

### S02 候補

- 1本のリスト。見出しもバッジも「未訪問」「訪問済み」「残りスタンプ」は出さない。
- 各カードはキービジュアルの切り抜き、季節を含んだ題、地区、理由、所要、移動、歩行、休憩、混雑、食または現地の人を出す。
- 現地モードの見出しは「いまから行ける場所」。帰宅後は「次の旅の候補」。

### S03 3枚

- 理由ごとに初期案を最大3枚出す。該当がなければそのカードは出さない。空カードは作らない。
- 各カードで理由と場所を、出せる候補だけから入れ替える。
- 「この1枚にする」で保存対象を選び、「編集した1枚を保存する」で1枚だけ残す。
- ボトムナビ中央の円形「編集」から開く。選択中は青い枠で示す。
- 保存ボタンは固定ボトムナビより上に固定し、スマートフォン幅でも遮られないようにする。

### S04 約束

- 保存した1枚を表示する。
- 見ている季節と一致すれば、条件が整った旨をアプリ内に書く。
- 一致しなければ、その季節にアプリを開いたときに表示する旨を書く。
- 保存を消せる。

### S05 季節の記録

- 場所と季節の組を、この端末に追加または外す。
- 同じ組を二度は残さない。
- 追加と削除のあと、候補と3枚の初期案を作り直す。

## 3. データ設計

カタログはコード内の固定データ。端末に残すのは次の形だけ。

```json
{
  "mode": "after",
  "season": "autumn",
  "showBurdenFirst": false,
  "history": [{ "spotId": "shio", "season": "autumn" }],
  "saved": { "spotId": "shio", "season": "winter", "reason": "season" },
  "noticeSeen": false
}
```

| 項目 | 値 | 意味 |
| --- | --- | --- |
| mode | `onsite` / `after` | 現地 / 帰宅後 |
| season | `spring` `summer` `autumn` `winter` | この端末で見ている季節 |
| showBurdenFirst | boolean | 移動負担を先に出す |
| history | spotId と season の配列 | 訪れた季節。最大40件 |
| saved | spotId, season, reason | 編集後に残した1枚。未保存は null |
| noticeSeen | boolean | 条件一致のアプリ内表示を確認したか |

初期の履歴は、星綾の潮見台の秋、虹灯りの夜市の秋、風詠みの灯台の夏。

スポットは7件。各スポットは春夏秋冬に1体験ずつ持つ。体験は `season`、`reason`（`season` / `food` / `people`）、題、説明、食、現地の人や催し、所要分、移動、歩行、休憩、混雑を持つ。

読み込み時に、カタログに無い spotId、season、reason は捨てる。壊れたJSONは初期状態に戻す。

## 5. サジェスチョン規則

1. 履歴に同じスポットと同じ季節があれば、その体験は出さない。
2. まだその季節に行っていなければ、未訪問という言葉を付けずに候補へ入れる。
3. 現地モードは、見ている季節の体験だけを出す。今の季節にすでに行った場所は出ない。
4. 帰宅後モードは、別季節の訪問済みスポットと、まだ行っていない季節のスポットを同じ配列に混ぜる。
5. 並びは、現地なら今の季節、帰宅後なら次の季節を先にし、その中は所要が短い順。
6. 初期3枚は、季節が変わる続き、食が乗る続き、人がいる続きの先頭候補。無ければその枚は出さない。
7. 理由を変えたとき、同じ場所でその理由が出せれば場所を保つ。出せなければ、その理由の先頭に変える。
8. 低満足の代理として、移動負担を先に表示できる。候補の採否は変えない。

## 6. セキュリティ

- 認証は要件で不要。個人名、メール、トークンは持たない。
- CSP で自ファイル以外の読込を拒否する。
- 画面の文字列は `textContent` と `createTextNode` だけを使う。`innerHTML` は使わない。
- 保存値は表示前にカタログIDへ照合する。
- 自由記述を受け取らないため、入力起点のXSS面は選択肢の改ざんに限る。改ざんされたIDは候補生成で無視する。

## 8. 試験シナリオ

### TS01 初回の帰宅後

1. `v002/index.html` を開く。
2. 季節が秋、モードが帰ったあとであることを確認する。
3. 候補を開き、秋の潮見台と秋の夜市が無く、冬の潮見台があることを確認する。
4. 画面内を「未訪問」「訪問済み」で検索し、ヒットしないことを確認する。

### TS02 現地の今

1. はじめにで「いま現地」を選ぶ。
2. 候補が秋の題だけであることを確認する。
3. 秋に記録済みの潮見台と夜市が含まれないことを確認する。

### TS03 編集して1枚残す

1. 3枚を開く。
2. 1枚の理由または場所を変える。
3. その1枚を保存する。
4. 約束画面に、編集後の題だけが出ることを確認する。

### TS04 季節が来たとき

1. 保存した1枚の季節を、はじめの季節切替で選ぶ。
2. 「約束の季節になりました」がアプリ内に出ることを確認する。
3. 確認したあとに消えることを確認する。通知の許可ダイアログは出ない。

### TS05 記録の追加

1. 季節の記録で、まだ残していない場所と季節を追加する。
2. 候補から、その場所のその季節が外れることを確認する。
3. 外すと、再び候補へ戻ることを確認する。

## 9. 制約事項への対応

| 制約 | 対応 |
| --- | --- |
| クラウド、外部API、外部DB、外部ストレージ禁止 | 静的ファイルと localStorage のみ |
| PHP禁止 | HTML、CSS、JavaScript |
| スマホとタブレットのWeb | 幅に追従。確認はブラウザの画面幅 |
| 認証不要 | ログイン画面を置かない |
| XSS対応 | CSP、textContent、ID検証 |
| ライセンス | 自作コードと自作SVGのみ |
| コメント | 各ファイルの動作単位で記載 |
| 複雑にしない | カタログ、規則、保存、描画の4ファイル |
| 風景とすりガラス | 大型SVGキービジュアル、半透明カード、ぼかし、角丸、控えめな影、白ボタン |
