# MataTabi 設計書（v013）

N西市の観光客向けWebアプリ。ヘッダーのアプリ名は仮に「MataTabi」とする。観光客アプリに認証は置かない。管理画面だけ担当IDと合言葉を使う。再訪は主催者が施策として設計し、KGIは同一ブラウザの季節またぎ件数とする。

ホームは、街並みの背景の上に、言語選択、全幅の街からのおしらせ（表示時は1件）、2列の旅の好みと再訪プラン、2列の思い出と探すを置く。思い出と探すの各カードは写真を2列×2段の最大4枚にする。幅390pxでもカードは2列のままにし、ホームはスクロールせずに収める。候補の詳細と記録の詳細だけを、すりガラスのモーダルで開く。表示言語は日本語、英語、中国語、韓国語、フランス語、イタリア語から選ぶ。

端末内の本人履歴・旅行スタイルと、同梱した匿名の合成旅行者データを組み合わせ、説明可能な再訪候補を出す。合成データは実在の旅行者や調査結果ではなく、予測精度を示すものではない。

## 1. システム構成

処理はブラウザと、このPCのNode.jsで行う。クラウドと外部ホストのDBは使わない。参考口コミ、発信するお知らせ、管理担当の合言葉ハッシュとセッション、氏名のない端末キーのハッシュと再訪KGIは、このPCの SQLite に置く。観光客向けアプリにログインは置かない。管理画面は `127.0.0.1` の別ページで、担当IDと合言葉のあとだけ操作できる。

## 2. 画面設計

背景はビューポート全体に `img/town.jpg` を敷き、その上に藍の薄いグラデーションを重ねて文字の可読性を保つ。内容の列は幅520pxまで中央に置く。カード、ヘッダー、下部ナビは白のすりガラス、角丸、控えめな影で統一する。対応ブラウザでは `backdrop-filter` を使い、非対応では白の不透明度を上げる。

下部ナビは観光客も管理画面も4項目で固定する。各項目は24pxのアイコンと文字を持ち、押す領域の高さは56px以上にする。選択中は白い地に藍の枠を付ける。本文の下にはナビの高さ分の余白を置き、最後の操作がナビに隠れないようにする。

文字はカタログ、検証済みの合成データ、固定文だけを `textContent` で出す。利用者の自由入力欄はない。

### S01 ホーム

- ヘッダー左にアプリ名「MataTabi」を出す。右に「言語を選択」を置く。押すと日本語、English、中文、한국어、Français、Italiano から選べる。選択肢は各言語の表記で固定し、選んだ言語は端末内に保存して画面全体へ反映する。
- 「街からのおしらせ」は表示時だけ全幅で、公開中お知らせの先頭1件を出す。右上の × でホームから消せる。新しい発信や更新があると、ホームに戻し、下部ナビの「お知らせ」に赤い点を付ける。お知らせタブを開くと点は消える。プッシュ通知は送らない。導入文と端末注記はホームに出さない。
- その下を2列にする。左は「旅の好み」（1行の要約と「登録」または「変更」）、右は「再訪プラン」（保存済みなら写真1枚と「編集」、未保存なら「発見から選ぶ」）。
- さらに2列で、左は思い出、右は探す。各カードの写真は2列×2段の最大4枚。ボタンは「思い出」と「探す」。催しがある候補は、その催し名を写真の説明にする。サムネイルを押すと記録または候補の詳細モーダルが開く。
- 幅390pxでもカードは2列のままにし、1列へ積み直さない。ホームはスクロールせずに収める。
- ホームのカード自体はモーダルにしない。

### S02 思い出

- 場所と季節の組を、この端末に追加または外す。
- 同じ組を二度は残さない。
- 行を押すと記録の詳細モーダルが開く。

### S03 発見

- 現地と帰宅後、見ている季節をここで切り替える。現地では季節欄に「今の季節」、帰宅後では「次行きたい季節」と表示する。
- 「ほかの候補」は、選んでいる季節の体験だけを出す。
- 帰宅後のときだけ、季節を統一したおすすめ再訪プランを最大3案表示し、各案で異なる2～3か所の画像を並べる。現地では再訪プランを出さない。
- 提示プランを選ぶと、同じ発見ページ内に追加・削除・保存の編集欄を表示する。
- 合成JSONを利用できる場合はその旨を明記し、失敗時は「端末内の記録だけ」と明記する。
- 候補は1本のリスト。見出しも行も「未訪問」「訪問済み」とは書かない。ホームの発見ボタンは「探す」とする。
- 行を押すと候補の詳細モーダルが開く。
- 「3枚から1枚を残す」で編集画面へ進む。

### S04 お知らせ

- 下部ナビの4項目めは「お知らせ」。
- 名店の新メニュー／季節のメニュー、地元の最新情報、季節のイベントを、このPCから発信した公開中の文として出す。
- 取得に失敗したときだけ、カタログの初期お知らせへ戻す。
- 実在の店名・人物名・祭名は使わない。
- 行を押すと、すりガラスの詳細モーダルが開く。
- いま見ている季節の話題を先に並べる。
- 公開文の新規発信や更新があると、下部ナビに赤い点を付ける。このタブを開くと点は消える。

### S05 3枚の編集

- 理由ごとに初期案を最大3枚出す。該当がなければそのカードは出さない。
- 各カードで理由と場所を、出せる候補だけから入れ替える。
- 「編集した1枚を保存する」で1枚だけ残し、お気に入りへ戻る。
- この画面は下部ナビの項目にしない。編集中は「発見」を選択中にする。

### S06 旅の好み

- 同行形態、使える時間、移動負担、興味（最大4件）、混雑の好みを選択肢だけで登録する。
- 氏名、年代、性別、現在地、自由記述は受け取らない。
- 選択のたびにこの端末へ保存し、「登録する」で発見画面へ進んで再訪候補を確認する。
- 下部ナビには追加せず、ホームを選択中として扱う。

### S07 発見内の再訪プラン編集

- 発見の提示プランを選ぶと、ページ遷移せず発見内に編集欄を開く。ホームの保存済みプランから編集する場合は、発見へ移動して編集欄を開く。
- プランの季節は変更せず、同じ季節の場所を1か所からカタログ内の全場所まで選ぶ。
- 選択中の場所を削除し、カタログから別の場所を追加できる。
- 最後の1か所は削除できず、カタログ内の同じ季節の場所をすべて追加できる。
- 編集結果は端末内へ保存し、発見ページに留まる。保存結果はホームから確認・再編集できる。
- 「元の提案に戻す」で、編集を始めた時点の場所へ戻す。

### S08 お知らせ編集（管理画面）

- 観光客ナビには出さない。`admin.html` をこのPCのブラウザで開く。
- 担当IDと合言葉で入る。氏名は使わない。セッションは HttpOnly の Cookie。ログイン中だけ下部ナビを出す。ヘッダー右は「管理」とその右の「ログアウト」。ログイン前は「担当ログイン」だけにする。
- ナビは新規作成、編集、お知らせ一覧、様子の4項目。発信は新規作成と一覧の操作にする。
- ALL はすべてのお知らせと公開文の削除、担当の追加、様子の閲覧ができる。
- editor は自分が書いたお知らせだけ編集・発信停止・削除できる。初期カタログのお知らせは ALL のみ。様子の件数は見られない。
- 題名、本文、分類、季節、場所を選び、下書き保存または発信できる。
- 発信中の文は観光客のお知らせに出る。発信停止と削除は一覧から行う。
- 参考口コミとして公開された本文の削除は ALL だけが行う。評価の集計や口コミ投稿は置かない。
- 様子はブラウザ数、思い出、季節またぎ、お知らせ開封、プラン保存、見送りを件数と棒・表で出す。端末キーは出さない。外部のグラフライブラリは使わない。
- 様子の「どこから来ているか」は、渡されたスタンプラリーCSVの居住地域を人数の棒で出す。年代と性別を選ぶと、その層だけを人数の多い順に出す。回った場所は同じ人を1人として数える。氏名、メール、ユーザーIDは出さない。CSVは静的配信しない。観光客アプリは年代・性別・現在地を受け取らない。
- 見た目は観光客画面と同じすりガラスと白ボタンにする。一般的な管理コンソールにはしない。
- 観光客アプリにログイン画面は置かない。
- ALL は再訪施策（対象の場所と季節、狙い、仮説、期間）を残し、到達件数と季節またぎ件数（KGI）で判定する。端末の一覧は出さない。再訪施策と公開文の削除はお知らせ一覧に置く。

### 訪問後フィードバック

- 思い出の詳細モーダルで満足度1～5、「また行きたい / そうでもない」、コメント（200文字）を登録する。
- コメントは端末内に残せる。満足度と本文があるときだけ、同じPCの参考口コミへ公開できる。
- 詳細モーダルに、同じ場所・季節の参考口コミを出す。氏名は保存しない。
- 再訪候補詳細の「今回は見送る」は、その候補を再訪プランと保存済みプランから削除し、以後の再訪候補にも出さない。見送りは行動ログにも残す。
- 閲覧、保存、訪問、見送りの行動は最大200件まで端末内に保存する。

### 詳細モーダル

- 対象は候補の詳細と記録の詳細だけ。
- 背景の上に、すりガラスのカードとして開く。閉じる、背面を押す、Escape で閉じる。
- 開いているあいだ、背面の列は操作できない。

## 3. データ設計

カタログはコード内の固定データ。端末に残すのは次の形だけ。

```json
{
  "mode": "after",
  "season": "autumn",
  "preferences": {
    "party": "solo",
    "duration": "short",
    "mobility": "low",
    "interests": ["scenery", "nature"],
    "crowd": "avoid"
  },
  "history": [{
    "spotId": "shio",
    "season": "autumn",
    "reason": "people",
    "visitedAt": "2026-10-12",
    "satisfaction": 4,
    "revisitIntent": true,
    "comment": "夕景の語り部が分かりやすかった"
  }],
  "actions": [{
    "type": "view",
    "spotId": "shio",
    "season": "winter",
    "reason": "season",
    "at": "2026-11-09T05:00:00.000Z"
  }],
  "dismissedRevisits": [
    { "spotId": "shio", "season": "winter", "reason": "season" }
  ],
  "saved": { "spotId": "shio", "season": "winter", "reason": "season" },
  "savedPlan": {
    "season": "spring",
    "items": [
      { "spotId": "shio", "season": "spring", "reason": "season" },
      { "spotId": "yoichi", "season": "spring", "reason": "food" }
    ]
  },
  "noticeSeen": false,
  "noticeBaseline": false,
  "seenNoticeStamp": "",
  "hiddenNoticeStamp": ""
}
```

| 項目 | 値 | 意味 |
| --- | --- | --- |
| mode | `onsite` / `after` | 現地 / 帰宅後 |
| season | `spring` `summer` `autumn` `winter` | この端末で見ている季節 |
| preferences | party, duration, mobility, interests, crowd | 個人を識別しない旅行スタイル |
| history | spotId, season, reason, visitedAt, satisfaction, revisitIntent, comment | 訪れた季節と任意の評価・コメント。最大40件。comment は200文字 |
| actions | type, spotId, season, reason, at | view/save/visit/dismiss。最大200件 |
| dismissedRevisits | spotId, season, reason | 「今回は見送る」で再訪候補から外した組。端末内に保持 |
| saved | spotId, season, reason | 編集後に残した1枚。未保存は null |
| savedPlan | season, items | 同じ季節の1か所以上で構成する編集済み再訪プラン。未保存は null |
| noticeSeen | boolean | 保存した1枚の季節案内を確認したか |
| noticeBaseline | boolean | 公開お知らせの指紋を一度取り込んだか |
| seenNoticeStamp | string | お知らせタブで確認した公開文の指紋 |
| hiddenNoticeStamp | string | ホームの街からのおしらせを閉じたときの指紋 |

初期の履歴は、星綾の潮見台の秋、虹灯りの夜市の秋、風詠みの灯台の夏。

スポットは7件。各スポットは春夏秋冬に1体験ずつ持ち、嗜好照合用のタグを持つ。サムネイルのパスは `img/spots/{spotId}.jpg`。背景は `img/town.jpg`。

読み込み時に、カタログに無い spotId、season、reason、許可リストに無い嗜好、範囲外の満足度は捨てる。壊れたJSONは初期状態に戻す。v013が未保存なら、v012の履歴と保存したプランを検証して移行する。

### 合成サンプル

`data/sample-travelers.json` は12人・44訪問の動作確認用データで、`meta.synthetic` を必須とする。

| 項目 | 内容 |
| --- | --- |
| travelerId | `sample-001` のような合成ID |
| style | party, duration, mobility, interests, crowd |
| visits | spotId, season, reason, satisfaction 1～5, revisitIntent |

実在人物、氏名、連絡先、正確な位置、年代、性別は収録しない。JSONの取得・検証に失敗した場合、類似旅行者成分を0点として本人履歴と嗜好だけで提案する。

## 5. サジェスチョン規則

通常の発見候補はv003の規則を維持する。再訪候補は別の純粋関数で計算する。

1. 履歴がある場合、訪れたことがあるスポットだけを再訪候補にする。履歴がない場合は、嗜好、季節、所要時間でコールドスタート候補を作る。
2. 同じスポットの別季節は「新しい体験」として優先する。
3. 同じスポット・同じ季節は、本人の `revisitIntent` が true の場合だけ再提案する。
4. 現地モードでは、見ている季節以外を再訪候補から外す。
5. 類似旅行者は、回答済みの旅行スタイルだけを使って類似度を計算し、上位5件を参照する。
6. 興味の一致はJaccard係数、その他のスタイルはカテゴリ一致で計算する。
7. 総合点は本人の嗜好・履歴・行動40点、類似サンプル30点、別季節/新体験20点、所要・移動・混雑の適合10点とする。
8. 合成JSONが使えない場合、類似サンプル成分を0点にして処理を継続する。
9. 同点は、見ている季節、所要時間の短い順で安定して並べる。
10. 「前回とは違う春の体験」「好みの食に合う」「似た旅行スタイルの合成サンプルで好評」など、実際に点へ使った根拠を最大2件表示する。
11. 合成データからの結果を「人気」「予測」「実績」とは書かず、「参考提案」と明記する。
12. 順位順の候補を季節別にまとめ、同じ場所が1案内で重ならないように2～3か所を選び、最大3案の再訪プランにする。

## 6. セキュリティ

- 観光客アプリに認証は置かない。個人名、メール、機種情報、指紋は持たない。
- 端末キーは `crypto.getRandomValues` の32バイト。サーバは SHA-256 ハッシュだけを UNIQUE で持つ。管理画面にキーは出さない。
- 管理画面だけ担当IDと合言葉を使う。合言葉は scrypt、セッションは SHA-256 したトークンを SQLite に置き、Cookie は HttpOnly と SameSite=Strict。
- 管理の変更系は Origin を確認する。失敗したログインは担当IDごとに回数を制限する。
- editor の削除・編集はサーバ側で作成者を確認する。画面のボタン非表示だけに頼らない。
- CSP で自ファイル以外の読込を拒否する。
- 画面の文字列は `textContent` と `createTextNode` だけを使う。`innerHTML` は使わない。
- サムネイルのパスはカタログの spotId だけから組む。
- 保存値は表示前にカタログIDへ照合する。
- 自由記述を受け取らないため、入力起点のXSS面は選択肢の改ざんに限る。改ざんされたIDは候補生成で無視する。
- 旅行スタイルは個人を識別しない選択肢に限定し、氏名、年代、性別、連絡先、現在地は保存しない。様子の居住地域グラフだけ、渡されたCSVの件数を出す。氏名とIDは画面に出さない。
- 合成JSONは `meta.synthetic: true`、既知のID、満足度1～5を満たすデータだけを推薦へ使う。
- 行動ログは端末内だけに最大200件を保存し、外部へ送信しない。
- 静的配信は `127.0.0.1` だけで待ち受け、ディレクトリ外の読込を拒否する。
- 口コミAPIはプレースホルダで実行する。spotId と season はカタログ照合、本文は200文字、満足度は1～5。氏名列は持たない。
- `.sqlite` ファイルは配信しない。口コミは最大500件。お知らせは最大200件。担当は最大20件。端末は最大2000、施策は最大50。匿名イベントは Origin 確認と回数制限。
- お知らせと公開文の入力は長さ制限と制御文字除去を行い、画面は `textContent` で出す。
- 管理APIは同一オリジン、プレースホルダSQL。観光客画面からは呼ばない。合言葉の平文は保存しない。

## 9. 制約事項への対応

| 制約 | 対応 |
| --- | --- |
| クラウド、外部API、外部ストレージ禁止 | 静的ファイル、localStorage、このPCの SQLite |
| このPCの SQLite / PostgreSQL は可 | 口コミ・施策・端末キーのハッシュは SQLite。PostgreSQL は未使用 |
| PHP禁止 | HTML、CSS、JavaScript |
| スマホとタブレットのWeb | 幅に追従。確認はブラウザの画面幅 |
| 認証不要 | 観光客アプリにログインを置かない。管理画面は担当セッション必須 |
| XSS対応 | CSP、textContent、コメントの長さ制限と制御文字除去、ID検証 |
| ライセンス | 自作コードと既存作品を参照しないオリジナル画像のみ |
| コメント | 各ファイルの動作単位で記載 |
| 複雑にしない | カタログ、通常候補、保存、サンプル読込、再訪推薦、描画を役割別に分離 |
| 全面の風景とすりガラス | `town.jpg`、グラデーション、半透明カード、白ボタン |
| 詳細だけモーダル | 候補詳細と記録詳細。ホームの2枚はページ内 |
| 非対応時の可読性 | `backdrop-filter` が無いときは白を濃くする |
| クラウド上の外部DB禁止 | 口コミとお知らせとKGIはこのPCの SQLite。SQLはプレースホルダ |
| 個人情報の抑制 | 観光客アプリは非識別の旅行スタイルと乱数の端末キーだけ。氏名・年代・性別・現在地は受け取らない。様子の居住地域は渡されたCSVの件数だけで、氏名は出さない |
